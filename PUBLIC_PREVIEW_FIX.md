# Public preview access

## Verified live cause (2026-10-13)

At `https://myhostage.ca/video/`, anonymous public video and photo list requests
returned 200. The next request used by `StorageImage`,
`POST /rest/v1/rpc/get_storage_base_path` with `{"p_kind":"images"}`, returned
401, JSON code `42501`, “permission denied for function get_storage_base_path”.
Consequently the frontend never attempted to sign/load those public images.

Probing the same resource paths directly with the deployed anonymous API key
returned 200 from Storage signing and 200 `image/webp` from the image URLs:
five video posters and four photo previews. These signed images are usable
without an authenticated account. The image responses carried ETags. No login
redirect, empty image response, MIME mismatch, CORS restriction, or CSP block
caused the reproduced failure. The browser visibly showed fallback icons with
no `<img>` preview elements. Public Files loaded its folder icon anonymously;
its only publicly shared folder was empty, so live file bytes/generated previews
could not be sampled there.

The code also had two stale states: `StorageImage` retried only when paths/URLs
changed, and `VideoPoster` permanently removed `StorageImage` after a failed image
request. Neither responded to a changed login session.

## Change

The forward migration `20261013010000_public_media_preview_access.sql` grants
anonymous execution only on the existing prefix lookup, which returns the image
or video prefix. Admin settings/table access remains private. A narrowly scoped
Storage read predicate matches public photo originals/previews/thumbnails and
public video posters to exact configured object keys. It supports empty and
multi-segment prefixes. Private, staging, arbitrary sibling, file-preview and
Messenger objects gain no access. Existing owner/shared policies remain intact.

Preview components retry failed requests on session, path or permission changes;
the video's permanent failure wrapper is removed. Public lists refetch quietly
on account changes. Public file browsing refetches while retaining its public
scope. Successful public images/file posters are retained across auth changes;
private images are keyed by account. File preview requests restart and cancel
previous work when auth changes. Retries are event-driven, with no refresh loop
and no `window.location.reload()` workaround.

Prefix and signing requests bypass the browser HTTP cache. Caddy marks only
those POST metadata/credential responses `private, no-store` and adds `Vary:
Authorization`. Existing image-byte caching remains unchanged. File preview and
public-file endpoints already authorize by the source's public opaque ID and
return `no-store`; their permissions and conversion/cache identity are unchanged.
No existing image bytes, thumbnails, sources or generated preview jobs are
replaced/regenerated by the migration.

## Verification

`tests/public-preview-access.mjs` uses the actual settings and new migrations in
isolated PostgreSQL/PGlite. It verifies the reproduced denial before the fix,
anonymous lookup after it, protected admin settings, public/private/staging
separation, existing owner reads, exact multi-segment keys and visibility
revocation. The suite is included in `test:core`.

The local browser fixture uses the real preview/card/list components. Browser
checks verified anonymous video/photo display and refresh; recovery from an
injected image 403 after login; repeated login/logout; private content removal;
public file image/icon display and reuse; and anonymous generated PDF rendering.
Desktop and a 390px viewport were checked. The live site was inspected before
deployment; no real account credentials or user content were changed.

Rerunnable browser regression: `node scripts/run-ui-regressions.mjs public-previews`.
For Firefox set `BROWSER_ENGINE=firefox`; for Edge set `BROWSER_CHANNEL=msedge`.
Install the corresponding Playwright browser first. The current browser-tool
checks do not certify Firefox/Edge separately or physical mobile devices.
CI includes the browser regression in Chromium and a separate Firefox step.
The local production build, full ESLint and TypeScript checks passed. All core
regression suites passed (the ZIP suite required selecting the bundled Python
runtime). `tests/public-preview-caching.mjs` checks actual Caddy headers with a
synthetic upstream, including preserving caching for signed-image GET requests.

## Deployment

The site remains unfixed until the migration and frontend/proxy changes deploy.
The repository's normal main-branch CI → Deploy workflow backs up the database,
applies the migration and rebuilds the app/proxy. No SSH session or production
change was made during this fix. After deployment repeat anonymous browsing and
refresh on all public routes, check the prefix RPC returns 200, and use approved
accounts for real login/logout and private/shared access checks.
